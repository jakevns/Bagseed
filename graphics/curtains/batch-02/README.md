# Curtain batch 02 — proposal awaiting approval

Exactly two sets: Floral Curtains (`floral`, $18) and Sheer Curtains (`sheer`, $14), the next existing catalog choices after approved Basic/Blackout. The user requested two sets per batch, including animations and store artwork, with pictures for approval before pushing. Floral uses warm cream cotton printed with small rose-and-sage flowers; Sheer uses translucent ivory voile with looser hem movement. The approved first curtain atlas and sage/cream/oak bedroom were used as visual references.

`assets/curtains-atlas.png` is the original generated transparent image, retained without editing. SHA-256, dimensions and registered source rectangles are in `sources/manifest.json`. Each source rectangle is fitted into a 72×61 logical display frame with its original proportions intact. The rod stays opaque and fixed. Cloth below the mounting strip uses the recorded opacity: Floral 1, Sheer .62, providing actual visibility of the live window through the fabric. The Floral print moves with the cloth. Both sets sway gently in calm weather, more strongly in Windy weather, and remain still in reduced-motion mode; Sheer has a higher motion multiplier. The same art and opacity are used in static store previews.

This is a proposal only: `public/index.html`, game source, production metadata and Batch 01 renderer/artwork are unchanged. `tools/compile-curtains.cjs` now accepts a batch argument, defaulting to 01; the default still produces exactly the existing embedded Batch 01 script. The production builders still compile Batch 01 only. Batch 02 is injected solely into the preview browser by `node tools/preview-curtains.cjs 02`.

The preview checks both normal and Windy motion, fixed rods, reduced motion and nonopaque Sheer body pixels. It compares all five other choices, including the approved Basic/Blackout pair, against their pre-injection static, normal and Windy renderings. These earlier renderings are also recorded as SHA-256 hashes in `review/curtains-batch-02/prior-render-hashes.json` to protect them during integration. It checks both actual LeafCart cards on desktop and phone, including proportions. The approval board, individual store cards and validation report are retained in `review/curtains-batch-02/`.
